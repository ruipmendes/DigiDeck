Digi Deck learns to notice. A new Twitch notifications layer surfaces subs / raids / cheers / follows / stream start+stop as toast banners on the deck and push notifications on paired phones — the deck can now tell you something's happening even when you're deep in a game. Plus two polish items: OBS scene previews flip to opt-in, and dependency hygiene.

## Twitch notifications (new)

Streamers often can't look at the deck while playing. The notification layer closes that gap with two visibility surfaces:

**In-deck toast banners** — a floating banner slides down from the top of the deck UI (whichever page is open), 5 seconds, auto-dismisses. Visible from any page without tile-hunting. Per-event accent colors so a raid reads differently from a sub at a glance.

**Phone push notifications (Web Push)** — a vibration + lock-screen notification on paired phones, even when the deck PWA is backgrounded or the phone is locked. Each phone opts in individually via a new **🔔 notify** toggle in the deck header. Uses VAPID keys generated on first run; expired subscriptions prune automatically.

**Setup lives in the Twitch panel** → a new *Twitch notifications* section below the existing chat block, visible when the Twitch chat integration is connected. Per-event matrix of toggles:

| Event          | Toast | Push | Amount filter       | Cooldown |
| -------------- | :---: | :--: | ------------------- | -------- |
| Raid           |   ✓   |  ✓   | Min viewers         | seconds  |
| Sub            |   ✓   |  ✓   | —                   | seconds  |
| Cheer          |   ✓   |  ✓   | Min bits            | seconds  |
| Follow         |   ✓   |      | —                   | seconds  |
| Stream online  |   ✓   |  ✓   | —                   | —        |
| Stream offline |   ✓   |      | —                   | —        |

Each row has a **Test** button that fires a mock event through the dispatcher so you can verify a config without waiting for a real sub.

**Scope changes required** — EventSub reads need three new OAuth scopes: `moderator:read:followers`, `channel:read:subscriptions`, `bits:read`. Existing users will see a scope mismatch; Disconnect → Connect on the Twitch panel re-authorizes with the new set.

**Push requires HTTPS** — Service Workers + Web Push only work in secure contexts. The deck ships self-signed HTTPS already (see v0.11), and INSTALL.md now documents the Android `chrome://flags/#unsafely-treat-insecure-origin-as-secure` workaround for devices where the self-signed cert install path is broken.

## OBS scene preview thumbnails: now opt-in

Previously, scene preview thumbnails polled on every tile with an `obs` + `set-scene` action automatically. That was noise for streamers who wanted scenes without the live preview, and screenshot calls scaled with scene count.

Now each tile has a **"OBS scene preview"** toggle in its icon / image / accent appearance popover (visible only when the tile targets a scene). Default off. Existing scene tiles need the toggle flipped once to restore their preview.

Net: zero `GetSourceScreenshot` calls unless at least one tile has explicitly opted in.

## SecurityPanel: HTTPS restart nudge

The HTTPS toggle writes to config but the listener is created once at server boot. Toggling after boot left the UI claiming HTTPS was on while the server still answered plain HTTP (producing the maddening `ERR_SSL_PROTOCOL_ERROR` for anyone connecting over `https://`).

The panel now compares the saved toggle against the live listener's actual protocol and surfaces an amber "Restart required" callout when they disagree, pointing at tray → Quit → re-launch.

## Dependency hygiene

Non-breaking lockfile refreshes across server + client. Bumps adm-zip for the known 8-CVE batch, adds a `file-type` override to clean up the transitive chain from the nut-tree image stack. Both `npm audit` runs now report 0 vulnerabilities.
